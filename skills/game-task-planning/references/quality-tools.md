# 필수 코드 품질 검사

코드 변경과 도구 준비에서 읽는다. 코드 규칙(lint), 형식(format), 타입 또는 의미 분석(analysis), 주 제품 코드 테스트 범위(coverage)를 필수로 선택·연결·실행·검토한다. 구문 검사는 보조이며 이 네 가지를 대신하지 않는다. 공통 [필수 준비 계약](../../game-workflow-supervision/references/mandatory.md)이 연결과 부족한 준비를 관리한다.

현재 프로젝트의 실제 언어·엔진·버전·명령·설정·검사 대상과 사용 가능한 도구를 먼저 확인한다. 도구 이름만으로 기능 지원을 추정하지 않는다. 각 검사의 담당자, 실제 기능/지원 근거, 명령/cwd, source/config, 포함·제외, 실행과 유지보수 위치를 기존 정책에 연결한다. 미선택·미지원·미확인은 이유와 담당자를 남기고 해당 제품 코드 변경/수용을 막는다. 필수 검사를 optional/N/A로 바꾸지 않는다.

설정 준비와 실제 실행은 별도다. 새 설치·dependency 변경·대규모 서식 변경은 실제 권한을 확인하되 이미 받은 권한을 다시 묻지 않는다. 형식 검사는 차이를 검사하며 자동 수정 권한이 아니다. 작은 변경은 영향 범위의 충분한 검사를 사용하고 무관한 제품 검사·전체 빌드를 반복하지 않는다.

실제 실행은 [실행 증거](execution-evidence.md)와 [안정된 입력](delivery-contract.md#stable-verification-inputs)에 연결한다. source/tool/config/후보·정확한 command/cwd·exit/timeout·raw·완료 신호와 처리 파일을 확인한다. exit0·빈 작업·미지원 입력·setup 실패·미완료·오래된 PASS로 누락을 숨기지 않는다. adapter는 정상과 의미 있는 진단/실패·실행 오류 사례로 확인한다. 설정 플래그와 자체 검사는 독립 검증이 아니다.

coverage는 실제 주 제품 소스의 기대 파일 집합, 계측된 파일·단위/관측량/분모, 제외/미실행/계측 불가, 변환된 소스의 원본 매핑과 테스트 결과를 함께 기록한다. 참조판 한 파일의 측정을 실제 게임 전체로 확대하지 않는다. 미지원 단위는 미지원이며 임의 비율 기준을 새로 만들지 않는다. 높은 coverage는 독립 기대값·기능·엔진·기기 검증을 대신하지 않는다.

계획자는 네 가지의 준비/실행/담당을 기존 작업에 포함하고, 구현자는 현재 결과를 반환하고, 인프라 담당은 실제 지원/대상과 판독을 준비하고, 별도 검토자는 범위·누락·주장·현재 원본을 읽는다. 위키/워크플로우 문서 유지보수는 그 변경의 연결·구문·해시·행동 검사를 하며 제품 검사의 남은 준비를 함께 보고한다. 제품의 미충족 항목을 통과로 바꾸지는 않는다.
